# R0.5 权限收紧恢复安全增量

状态：合成数据开发范围，基于 R0.4 堆叠；不等于生产备份恢复已经交付。

## 目标

R0.5 只解决一个窄而关键的问题：冻结、撤回、撤下、收紧受众等已经成功的限制性变更，不能因为业务数据库回退、外部记录缺失或恢复介质被改变而被静默复活。

本增量新增三个互相核对的事实源：

1. 业务数据库中的当前限制状态与恢复水位；
2. 与数据库文件分离的只追加权限收紧日志；
3. 与前两者分离的可信水位文件。

每个数据库请求前，服务核对实例身份、连续序号和哈希链。任一介质缺失、损坏、不一致，或者存在未确认事件时，实例进入或保持隔离，数据库业务接口返回 `503`；`/api/v1/health` 只代表进程存活，`/api/v1/ready` 才执行不公开细节的恢复就绪核对。

## 纳入的限制性操作

- 冻结成员；
- 修改或撤回已分享原话；
- 修改已选候选转述或改变表达选择，从而撤掉旧分享；
- 取消资料送审；
- 撤下资料或收紧资料受众；
- 撤回双方私有纠错。

准确性确认、分享授权、理解核对、立场、正式批准和任务接受仍是不同操作。本日志只证明限制性状态的持久化次序，不把任何操作解释成其他人的同意。

## 提交次序与失败语义

一次包含限制性变更的请求按以下顺序执行：

1. 将业务限制、常规审计、待确认事件和 `isolated=true` 一起提交到业务库；
2. 在进程锁内校验外部日志和可信水位，追加事件并 `fsync`；
3. 原子替换并同步可信水位；
4. 将新水位写回业务库，删除待确认事件并解除隔离。

第 2 至第 4 步任一步失败时，请求返回 `503`。第 1 步已经提交的限制仍然有效，实例保持隔离，不继续提供可能复活旧权限的业务读写。

## 隐私边界

外部日志只保存事件标识、动作、对象类型和标识、操作者标识、对象版本，以及恢复限制所需的最小状态。不得保存原话、候选转述、理解复述、纠错正文、资料正文、口令、令牌或模型输入输出。

日志中的标识仍属于运行数据，不进入 Git，不应公开。它不是面向成员的个人操作记录，也不是通用审计导出。

## 本增量明确不交付

- 不提供自动恢复、自动合并或跳过不一致的开关；隔离后的恢复工具留待下一增量；
- 不宣称仅凭日志即可重建完整数据库；完整加密备份、密钥托管和恢复演练仍未完成；
- 不覆盖 PostgreSQL、多节点、网络文件系统或对象存储；R0.5 仅支持单进程、POSIX 文件锁和本机文件型 SQLite（Windows 直接运行未支持，可使用 Linux 容器）；
- 日志在每个数据库请求前完整校验，尚无检查点或安全轮换；事件规模和性能只适合当前合成开发验证；
- 不保护管理员对操作系统、数据库和两个恢复目录同时拥有控制权的情形；
- 不为过去已经发生但未记录的 R0.4 操作补造历史事件；升级水位从零开始，升级前仍须停机备份；
- 不改变真实试用、正式批准和数据治理尚未验收的事实。

## 验收标准

- 正常限制性操作同时推进业务库、连续日志和可信水位；重启后继续通过核对；
- 日志不出现合成测试中的秘密正文；
- 外部追加失败后，限制状态已保存，实例隔离，后续登录和业务读取均为 `503`；
- 删除或改变日志、删除或改变可信水位、回退业务库水位，均不能恢复旧访问；
- 非限制性写入不产生权限收紧事件；
- 旧 R0.4 流程回归通过，且新增表不修改旧业务记录。
