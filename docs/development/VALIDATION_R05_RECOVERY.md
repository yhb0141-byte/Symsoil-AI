## 专项证据

| 场景 | 实际结果 |
| --- | --- |
| 私稿创建和未分享编辑 | 不产生权限收紧事件 |
| 已分享原话撤回 | 业务库、连续 JSONL 和可信水位共同推进到序号 1 |
| 最小化与文件权限 | 合成秘密正文不在日志；目录为 `0700`，日志、水位和锁为 `0600` |
| 外部写入故障 | 请求返回 `503`；成员冻结和会话撤销已在业务库生效；待确认事件与隔离状态保留 |
| 隔离后的访问 | 既有会话、全新登录及 `/api/v1/ready` 均为 `503`；`/api/v1/health` 仍只报告进程存活 |
| 日志或水位被改变 | 下一数据库请求返回 `503` |
| 恢复介质被改为其他本机用户可读 | 下一数据库请求返回 `503` |
| 业务水位被回退 | 当前外部日志／水位与业务库不一致，返回 `503`，不能静默恢复旧访问 |
| 正常重启 | 相同数据库及两份外部介质通过核对，登录与就绪接口正常 |

完整回归还覆盖现有冻结、表达撤回、候选失效、资料撤回／收紧、纠错撤回、并发撤权与模型返回前再鉴权路径。它证明当前实现没有破坏这些合成流程，不证明磁盘、文件系统或真实故障下的持久性。

## 未验收与停止条件

- 隔离后没有自动或人工批准的重放／对账工具；遇到 `503` 应停止服务并保全三份介质，不能编辑水位、删除待确认行或截断日志。
- 整组恢复到旧时间点仍可能丢失该时间点后的撤权；完整加密备份、当前撤权重放和恢复演练未交付。
- PostgreSQL、Windows 直接运行、多进程、多节点、网络文件系统、日志轮换和大规模性能未支持。
- 日志完整性依赖业务库、日志目录和可信水位不被同一攻击者同时控制；硬件信任根、签名和密钥托管未实现。
- 未处理真实社区资料、真实账号、真实模型权重或生产部署。正式决定批准、行动开始条件和共同记忆授权仍是下一阶段，不能由此标记完整 R1。
