# R0.3 本机运行与交接

## 责任和资产

源代码与文档由本仓库版本管理。运行数据库、演示口令及账号邀请口令保存在运行者掌握的本机环境中，不提交到公开仓库。GitHub 仓库账号不等于应用管理员账号。R0 仅使用合成数据；后续真实社区实例须分别确定资产持有人、系统维护人、资料审核人和议题主持人。

应用管理员可以创建一次性注册邀请和冻结账号，不能因管理员身份查看别人的私人表达。邀请口令只交给预期注册者；其有效期和一次性状态由服务端检查。口令遗失恢复、多因素认证和管理员转交尚未实现，不能把开发演示当作已完成账号接管。

## 日常操作

1. 初次运行按根 README 安装依赖、构建网页和初始化空的合成数据库。已经有数据时，初始化命令拒绝覆盖，不能用重复初始化重置口令。
2. 启动使用 `./scripts/start.sh`，默认只监听本机 127.0.0.1。它不安装依赖，默认关闭 AI。浏览器打开本机地址；主动配置本地 Ollama 后才会调用该本机服务，配置与离线条件见 `LOCAL_MODEL.md`。
3. 修改源码后运行 `./scripts/check.sh`，前端构建完成后重启服务。R0.3 在 R0.2 上只增四张资料表，旧合成库可在启动时增表；先停机备份，核对提交号，再验证已有对象数量与读取。旧资料没有元数据时保持隔离，恢复已知原始演示资料须按下面的显式步骤执行。尚无通用迁移／降级机制，后续表结构变更不能直接在已有资料库试改。
4. 前台服务按 Ctrl+C 停止。Compose 环境使用 `docker compose stop`；`down -v` 会删除数据卷，不用于普通停止。
5. 查看应用健康状态使用 `/api/v1/health`。其 `ai_available: false` 是兼容旧接口的保守值，实际模型可用性在登录后查看独立 `/api/v1/ai/status`，由页面的“检查模型状态”操作调用。账号闲置达到五分钟后需重新登录。

R0 不开放公网。后续局域网试用需要明确的域名、HTTPS、精确的来源配置、访问范围和现场恢复演练。所有浏览器资源均从本机提供，但安装包、驱动和软件更新的完全离线分发仍是后续交付项。

退出时页面立即清除私人内容、页面内存证明和未完成请求。R0.2 所有认证读取同时检查 Cookie 与页面内存中的 `X-CSRF-Token`；退出后残留 Cookie 单独访问私人 API 会被拒绝，刷新或新标签也必须显式登录。证明不写入浏览器存储。

断网退出仍不能证明服务端会话已注销；页面会如实提示。恢复连接后应完成服务端注销，或清理站点 Cookie。该修复不等于公共设备的全面安全验收，也不能撤回他人已经看到或保存的内容。

## 合成数据库保存与恢复边界

### R0.2 合成资料升级

先停止 API，备份合成数据库及记录对应代码版本。使用同一个 `DATABASE_URL` 执行：

```bash
PYTHONPATH=services/api .venv/bin/python -m symsoil_api.cli migrate-synthetic-documents --demo
```

命令只为三份完全匹配原始 seed 的资料补齐版本、受众及明确标记的合成审核记录，并核对原始合成身份；再次执行不会重复。启动增表不会执行此命令。未知、正文改变或缺少元数据的旧资料不进入目录、计数、原文和模型上下文。它们仍保存在原数据库，后续应通过经审阅的迁移或本人重新整理、另行授权入库；不能用“全量默认公开”修复目录为空。

重新启动后分别登录作者、审核人及其他成员，核对资料范围和已有表达／任务。新演示库 seed 已带元数据，无需额外迁移。本步骤仅针对合成开发库，生产数据迁移、回滚和恢复仍未交付。

### 资料维护

“查资料”→“我的私人资料”先录入文字和来源、授权边界、用途、维护人及受众。另选合格审核人并确认精确送审版，审核通过才发布；已经批准过的版本不能直接重复送审，修改或重新开放需另存完整新版本。私人更新保留旧有效发布，发布新版后旧引用不可继续读取。

作者可撤回送审而保留已发布内容；收紧受众或撤下同时取消当前送审，阻止旧审核恢复访问。有效期到达后资料停止当前访问；本人可见最后版本历史。资料审核只决定入库范围，不批准正文中的社区决定或任务。

问答默认显示资料摘录，可主动选择已就绪的本地模型。回答不自动保存。引用打不开时重新查当前资料；正文来源只能由人工核实，结构测试不能保证模型语义正确。其他设备已看到或保存的内容无法追回。

单机 SQLite 开发库默认位于 `data/symsoil.db`。保留开发现场时，先停止 API，确认没有进程继续写入，再复制整个 `data` 目录到运行者控制的独立位置，并记录代码提交号。恢复也在停机时执行，只恢复与该代码版本匹配的合成库。备份不进入公开仓库。

这不是已验收的生产备份系统。定时备份、加密、异地保管、恢复点目标、恢复时间目标、PostgreSQL 恢复和数据删除传播必须在 R1/R2 专项落实。Docker 的持久卷保存数据；本轮没有完成容器构建和卷恢复的验收。

## 逐项签收

完整交接的目标是：**社区指定人员可依交付资料独立运行、维护、备份、恢复和继续开发；不依赖乙方或未移交的第三方账号、权限、知识及协调。** 仍需持续购买或更新的第三方服务、驱动和组件应列出供应方、用途、费用、替代方法和离线条件，不能写成无条件“无需任何外部协调”。

| 签收项 | 应交付与验证 | R0.3 状态 |
| --- | --- | --- |
| 源码 | 仓库控制权、提交号、依赖文件、构建命令、测试记录 | 本次分支及 PR 交付；由仓库所有者保留控制权 |
| 账号 | 应用管理、系统管理、仓库管理分开；清单、持有人、恢复及交接测试 | 仅本地演示账号和注册邀请；管理员恢复未交付 |
| 权限 | 角色范围、谁能读取什么、撤权效果及本人测试 | 基础对象权限、读取双证明、冻结、版本失效、指定审核、资料固定受众／期限／撤下；独立撤权日志与恢复重放未交付 |
| 文档 | 产品书、接口、范围、启动、限制、变更记录归档 | 本次文档交付，后续变更随源码更新 |
| 运行环境 | 硬件资产、驱动、离线依赖包、配置与故障处理 | 开发安装、本机启动和可选 Ollama 适配；真实模型、硬件及离线包未验收 |
| 数据 | 本地持有、备份、恢复、导出及删除演练 | 合成库；生产数据接管未交付 |
| 独立操作 | 社区人员在乙方不在场时重建和恢复，按验收步骤签字 | 尚未现场验收，不能以代码测试代替 |

每项签收记录交付版本、验证人、验证时间、结果与遗留事项。未完成项继续列出责任人和期限，不因总体验收而自动视为完成。
