# R0 本机运行与交接

## 责任和资产

源代码与文档由本仓库版本管理。运行数据库、演示口令及账号邀请口令保存在运行者掌握的本机环境中，不提交到公开仓库。GitHub 仓库账号不等于应用管理员账号。R0 仅使用合成数据；后续真实社区实例须分别确定资产持有人、系统维护人、资料审核人和议题主持人。

应用管理员可以创建一次性注册邀请和冻结账号，不能因管理员身份查看别人的私人表达。邀请口令只交给预期注册者；其有效期和一次性状态由服务端检查。口令遗失恢复、多因素认证和管理员转交尚未实现，不能把开发演示当作已完成账号接管。

## 日常操作

1. 初次运行按根 README 安装依赖、构建网页和初始化空的合成数据库。已经有数据时，初始化命令拒绝覆盖，不能用重复初始化重置口令。
2. 启动使用 `./scripts/start.sh`，默认只监听本机 127.0.0.1。它不安装依赖，不联系模型或云端服务。浏览器打开本机地址。
3. 修改源码后运行 `./scripts/check.sh`，前端构建完成后重启服务。R0 没有数据库迁移机制；涉及表结构的开发变更使用独立合成数据库，不对已有资料库直接试改。
4. 前台服务按 Ctrl+C 停止。Compose 环境使用 `docker compose stop`；`down -v` 会删除数据卷，不用于普通停止。
5. 查看健康状态使用 `/api/v1/health`。状态 `ai_available: false` 表示当前未接入 AI，不表示故障。账号闲置达到五分钟后需重新登录。

R0 不开放公网。后续局域网试用需要明确的域名、HTTPS、精确的来源配置、访问范围和现场恢复演练。所有浏览器资源均从本机提供，但安装包、驱动和软件更新的完全离线分发仍是后续交付项。

退出时页面立即清除私人内容，但若网络中断，Cookie 和服务端会话可能仍有效。页面提示“服务器尚未确认注销”时，不应把当前浏览器交给他人。恢复连接后完成服务端注销，或关闭并清理该浏览器的站点 Cookie；只刷新页面不会撤销服务端会话。每次刷新及新标签都要求重新登录，解决的是界面自动恢复问题。凭证残留处理仍是 R1 公共设备验收项。

## 合成数据库保存与恢复边界

单机 SQLite 开发库默认位于 `data/symsoil.db`。保留开发现场时，先停止 API，确认没有进程继续写入，再复制整个 `data` 目录到运行者控制的独立位置，并记录代码提交号。恢复也在停机时执行，只恢复与该代码版本匹配的合成库。备份不进入公开仓库。

这不是已验收的生产备份系统。定时备份、加密、异地保管、恢复点目标、恢复时间目标、PostgreSQL 恢复和数据删除传播必须在 R1/R2 专项落实。Docker 的持久卷保存数据；本轮没有完成容器构建和卷恢复的验收。

## 逐项签收

完整交接的目标是：**社区指定人员可依交付资料独立运行、维护、备份、恢复和继续开发；不依赖乙方或未移交的第三方账号、权限、知识及协调。** 仍需持续购买或更新的第三方服务、驱动和组件应列出供应方、用途、费用、替代方法和离线条件，不能写成无条件“无需任何外部协调”。

| 签收项 | 应交付与验证 | R0 状态 |
| --- | --- | --- |
| 源码 | 仓库控制权、提交号、依赖文件、构建命令、测试记录 | 本次分支及 PR 交付；由仓库所有者保留控制权 |
| 账号 | 应用管理、系统管理、仓库管理分开；清单、持有人、恢复及交接测试 | 仅本地演示账号和注册邀请；管理员恢复未交付 |
| 权限 | 角色范围、谁能读取什么、撤权效果及本人测试 | 基础对象权限、冻结、分享撤回；完整角色治理未交付 |
| 文档 | 产品书、接口、范围、启动、限制、变更记录归档 | 本次文档交付，后续变更随源码更新 |
| 运行环境 | 硬件资产、驱动、离线依赖包、配置与故障处理 | 开发安装和本机启动；硬件及离线包未交付 |
| 数据 | 本地持有、备份、恢复、导出及删除演练 | 合成库；生产数据接管未交付 |
| 独立操作 | 社区人员在乙方不在场时重建和恢复，按验收步骤签字 | 尚未现场验收，不能以代码测试代替 |

每项签收记录交付版本、验证人、验证时间、结果与遗留事项。未完成项继续列出责任人和期限，不因总体验收而自动视为完成。
