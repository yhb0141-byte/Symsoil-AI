# 可选本地模型与表达建议

R0.2 提供真实 Ollama API 适配器，模型只为本人原话生成最多两份候选转述和待澄清问题。它不检索私人历史、不直接写入正式观点、不代替本人确认，也不改变任务或方案立场。人工候选与理解核对不依赖模型。

本轮验证代码、协议和失败处理；未在目标社区设备安装模型权重，也未验收真实推理质量、吞吐、显存或断网恢复。不能把适配器完成等同于本地智脑已经部署完成。

## 在已有本机设备试验

1. 维护者先准备可运行的 Ollama，并检查其实际服务配置。使用独立终端启动时，可以运行 `OLLAMA_NO_CLOUD=1 ollama serve`。已经由系统服务启动的实例须在那个服务中设置禁云项并重启，不能只在应用进程中设置变量。
2. 在允许联网的准备阶段安装经过核对的本地模型。例如上传方案中的候选 `qwen3.5:9b`：`ollama pull qwen3.5:9b`。本软件不会代为下载，也不会在模型缺失时调用云模型。模型及组件的许可、实际文件校验值和安装版本由部署者逐项归档。
3. 确认模型在本机列表中存在，再启动应用：

```bash
SYMSOIL_AI_ENABLED=true \
SYMSOIL_OLLAMA_MODEL=qwen3.5:9b \
SYMSOIL_OLLAMA_URL=http://127.0.0.1:11434 \
  ./scripts/start.sh
```

4. 使用合成账号打开“说想法”，明确输入本次背景、希望面向的语境和用途，先看模型状态，再主动请求建议。检查是否保留原话含义、拒绝和条件，是否把猜测写成动机。保存或修改候选后，由本人分别核对原话与所选转述，再预览要分享的唯一正文和受众。
5. 关闭模型，重新验证人工候选、本人核对、议题读取和听者复述仍可完成。真实设备验收另包含断开互联网、重启、权限与恢复测试。

模型型号是试验候选，不是性能保证。无需为了运行网页先买 GPU；先用已有设备测代表性表达，记录冷启动、生成耗时、可用内存及错误，再判断是否采购。具体设备配置与现场报价另行决定。

## 数据流与失败行为

适配器只允许维护者配置的字面 loopback HTTP 地址，拒绝公网、域名、URL 凭据、跳转和环境代理。单次请求只包含本人当前原话及主动填写的语境，模型不能获得数据库、其他成员草稿或应用管理凭据。应用限制并发、输出长度和请求时间，并在结果返回前再次核验本人会话及源版本。

JSON schema 约束加二次校验只检查结构，不保证文字准确或没有偏见。错误格式、超时、服务未启动、模型缺失或繁忙均显示失败，保留人工路径。没有云端兜底。模型守护进程及运行设备也需要维护者关闭云功能、检查路由与外发防护；回环地址本身不能证明守护进程绝不联网。

建议仅为待核对预览，不自动保存。未经改动的预览带有十分钟有效的服务端来源证明，保存后可标识本地模型来源；改动文字或语境后作为本人改写保存。证明绑定当前作者及原话版本，不能由客户端直接指定生成来源。服务重启使旧预览证明失效，此时可重新生成，或明确作为手写候选保存。

本轮只有同机适配器。Compose 默认未启用模型；容器中的回环地址指向该容器，不能照搬主机地址并假定连接成功。容器模型编排、不同机器间授权连接和生产部署在后续单独验证。
