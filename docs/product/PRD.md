# 共壤社区 AI 智脑产品书

产品需求与首版开发规格

文档版本：PRD V0.1　　编制日期：2026 年 10 月 5 日

产品版本：首期受控试用版　　适用团队：产品、设计、研发、测试、社区运营与接管人员

共壤社区 AI 智脑服务于共同生活和共同行动。我们希望不同文化语境、身份背景与专业经验的人，能够表达自己的处境、核对彼此的理解，讨论真实的差异，再形成有边界、能履行、可调整的约定。系统保存经授权的知识与共同经历，让后来的参与者能够理解事情为什么这样发生。

首版建设一个由社区掌握的本地网页工作台，完成“查资料、说想法、看议题、做事情、共同记忆、我的权限”六类活动。AI 提供查找、解释、转述、比较和拟稿；成员确认自己的表达和承诺，有权主体批准决定，运营人员维护资料与程序。关系中的理解、信任和情感，依靠真实互动及行动逐步形成。

本产品书把已有《建设与运营实施方案》转成可以设计、开发和测试的规格。首期按一个社区、20 至 40 名自愿成年参与者、2 至 3 个真实议题、90 天试点规划。文中工期、容量和性能为待验证的目标；开发可以先使用合成数据开始，真实试用在责任人与议事规则明确后启动。

## 01 产品定位与成功标准

### 产品要解决的问题

社区知识分散在个人经验和不同文档中，新成员不容易找到有效规则与实际负责人。不同背景的人使用相同词语时，可能在谈不同的风险、资源和生活经验。讨论形成的记录又经常混淆“听懂了”“没有回应”“同意尝试”和“愿意承担”。项目结束后，经验与情感可能随人员流动而散失。

我们通过可核对的表达、可追溯的决定和可重新协商的行动改善这些问题。产品应帮助成员知道自己正在参与什么、哪些内容由谁看见、下一步由谁负责。发生误解、分歧或困难时，成员可以纠正记录、表达保留、请求帮助，也可以停止使用 AI。

### 首版的价值主张

对成员，产品提供容易表达、能被准确理解的参与路径；对主持人，产品提供保留差异、比较选项和记录程序的工具；对行动组织者，产品把责任、资源、条件与变更放在同一处；对社区，产品形成可接管的公共知识与实践记录。

信任支持落实为五项可观察能力：表达可以被纠正，差异可以被保留，承诺有明确条件，变化可以重新协商，争议有独立求助入口。感谢、故事和共同回望提供情感表达的空间，成员可以选择分享，也可以选择不留下记录。

### 成功与停止的判断

试点至少完成两轮从议题提出到行动复盘的真实过程。每份正式决定能够追溯到规则、参与情况、批准者和具体版本；每项承诺能够追溯到承担者的主动接受；每条公开或共享记忆具备对应范围的授权。

使用评价关注参与者是否更能复述彼此的关注点，能否安全表达异议，是否清楚自己的责任以及如何改变约定。采用自愿反馈和人工观察，不给个人生成信任分、合作意愿分或贡献排名。短期试点只能提供改进依据，不能证明系统必然提升信任。

出现确认的越权读取、伪造批准或未经授权的正式发布，应停用相关能力并复测。若无人维护数据权限和备份，则暂停新增资料与 AI 生成，保留经检查的基本记录服务。是否继续扩展，由试点效果、成本与社区维护能力共同决定。

## 02 服务对象与角色边界

### 参与者与现实处境

首期邀请在地居民、长期成员、新加入者、不同专业的合作人员及承担照料劳动的人参与。角色来自实际工作和授权，不根据年龄、职业或教育背景推断能力与立场。持保留意见的人同样应有参与渠道。

手机网页是主要入口，同时支持公共终端、纸卡与授权代录。不会使用手机、拒绝录音或不使用 AI 的成员，可通过相同的议事程序表达意见。代录需注明代录人、本人确认方式和时间；协助者不能将自己的确认冒充当事人操作。

| 产品角色 | 可以执行的工作 | 权限边界 |
| --- | --- | --- |
| 普通成员 | 查阅授权资料，提交表达，参与议题，接受任务，管理自己的授权 | 仅访问本人及明确获准的对象 |
| 议题主持人 | 维护指定议题、组织核对、比较方案、整理决定草稿 | 不能据角色读取私人草稿、私密求助或未分享复盘 |
| 决定批准者 | 按已登记的议事规则批准指定范围的决定 | 只对授权对象和具体版本生效，不代替成员承诺劳动 |
| 项目协调人 | 维护行动约定、邀请承担者、核对资源与结果 | 邀请不等于分配，不得替本人接受任务 |
| 资料维护人 | 审核送审材料、维护版本、处理来源和纠错 | 审核权限定于获准送审内容，不包含所有个人记录 |
| 请求受理人 | 处理分配给自己的求助、程序异议和数据请求 | 默认仅见本人负责的请求及必要材料 |
| 账号管理员 | 邀请、冻结账号，按授权分配角色 | 账号管理不自动授予业务内容读取权 |
| 技术维护人 | 管理部署、备份、故障与恢复 | 如实披露底层权限，临时访问按运维程序留痕 |

一个人可兼任多种角色，但每次关键操作记录实际身份、对象及依据。涉及本人利益的程序审核和验收，按社区确认的回避规则另设复核人。软件维护者不自动成为决定批准者。

## 03 首版范围与发布节奏

### 范围基线

首版用文字完成完整协作过程。知识目录、关键词查询和结构化记录先可用，再接入本地 AI。核心功能全部支持人工填写，AI 按模块开关启用；语音、复杂图谱和跨社区连接不构成首版依赖。

| 模块 | 首版必须交付 | 首期限制 |
| --- | --- | --- |
| 账号与权限 | 本地登录、邀请、角色、对象授权、冻结、审计 | 单社区；不接外部社交登录 |
| 资料与问答 | 审核入库、分类与搜索、带来源回答、纠错 | 100 至 300 份获准材料；无全量聊天导入 |
| 表达与理解 | 原话、最多两种转述、本人核对、分享预览、听者复述 | 文字交互；共同词义先用议题内条目 |
| 议题协商 | 范围、观点、选项、异议、参与情况、公共屏 | 手工记录；不自动录音或表决 |
| 决定记录 | 规则快照、核对、条件检查、批准、版本与重议 | 支持登记的授权批准流程；复杂表决先人工留证 |
| 行动与复盘 | 项目约定、任务邀请、接受、变更、核验、复盘 | 资源人工确认；不做支付和自动分配 |
| 共同记忆 | 经验、故事、具体感谢、送审、授权、撤下 | 以文字为主；受众限定在本地受控服务内 |
| 帮助与管理 | 求助工单、个人导出、撤权、备份恢复、AI 停用 | 站内提醒；线下或人工联系补充 |

“可以公开”的素材标记与互联网公开发布分开。首期不建设面向互联网的生成式服务或公开故事门户。开发仓库仅存放代码、合成样本和获准公开文档，不能成为社区业务数据的备份位置。

### 三次交付

R0 为开发验证版，建议前两周完成登录、对象权限、人工议题与任务流程，用合成数据演示。R1 为内部测试版，在第 3 至 6 周补齐转述核对、知识检索、决定批准、记忆授权和离线恢复。R2 为受控试用与验收版，在第 7 至 13 周完成两轮真实行动、独立测试及接管。

这些阶段共享同一产品和数据模型，不开发互不相干的演示系统。每一阶段只开放已经完成验收的能力。人员减少或时间不足时，可以缩小真实议题数量、材料数量与同时生成数，不能将权限、版本、备份和本人确认挪到后续版本。

### 后续功能进入条件

语音与方言支持需完成当地使用者测试；地方观察、实践学习、生计核算与艺术共创需有明确运营者；跨社区互助先交换获准的方法和知识包。上述功能在试点证明有实际需求、有人维护及费用落实后另立需求，不以“未来可能使用”扩大首版数据采集。

## 04 贯穿全产品的真实场景

### 公共场地艺术工作坊

场景采用合成例子：艺术工作者希望周末举办工作坊，居民关心作息和场地清理，组织者需要确定可用时间、经费与参与责任。例子用于开发和测试，不代表共壤已经作出的决定。

| 环节 | 成员看到和执行什么 | 系统留下什么 |
| --- | --- | --- |
| 查规则 | 搜索场地使用办法，打开现行原文和负责人 | 已授权来源与版本，不产生场地预订 |
| 说想法 | 居民写下清理担忧，核对转述，选择提交议题 | 原话版本、确认版本、分享范围 |
| 核对理解 | 组织者复述担忧，居民更正或确认 | 理解核对记录，不生成支持票 |
| 看方案 | 比较调整时段、缩小规模、暂缓举办等选项 | 各方案成本、劳动、风险和未核实项 |
| 形成决定 | 查看异议、试行边界及批准程序，有权人批准一次试办 | 具体版本的批准记录与复盘日期 |
| 接下任务 | 受邀者确认清理范围、工具、报酬或自愿性质，再接受 | 明确承担者与任务条款版本 |
| 开展行动 | 协调人核查关键资源和承诺，成员报告困难或结果 | 开始条件、变更和核验记录 |
| 复盘与保存 | 个人先写反馈，选择共享摘录，再形成经验条目 | 行动调整、授权充分的共同记忆 |

若居民不愿把原话放到公共屏，仍可提交经确认的转述，或选择由指定主持人单独征询。若始终无法就时间达成约定，产品允许记录暂缓及未解决原因，不能用 AI 总结制造一致。

## 05 信息架构与通用交互

### 手机工作台

首页上方显示社区名称、连接状态和“需要我回应”的事项；中部是六个功能入口；下方显示近期可参与事项和人工协助。底部导航采用“首页、待回应、我的”三个固定位置，六项业务从首页进入，避免把全部模块塞入底栏。

待回应列表只列出本人有权接收且需要明确动作的事项，包括表达核对、理解核对、决定核对、任务邀请、授权请求及求助回复。每项显示请求人、具体对象、截止时间和动作效力。未处理的记录保持未处理，不自动转换为同意。

| 页面编号 | 页面或界面 | 主要操作 |
| --- | --- | --- |
| UI01 | 首页与待回应 | 打开任务、进入六个模块、联系协助者 |
| UI02 | 资料目录与问答 | 搜索、查看来源、继续澄清、反馈错误 |
| UI03 | 表达编辑与版本对照 | 保存原话、请求转述、逐项核对、预览分享 |
| UI04 | 理解核对与词义 | 提交复述、回应修正、查看适用语境 |
| UI05 | 议题详情 | 观点、方案、异议、决定、参与情况分区浏览 |
| UI06 | 主持界面与公共屏 | 选择材料、预览、投屏、结束展示 |
| UI07 | 决定详情与版本比较 | 核对记录、批准、查看旧版、申请重议 |
| UI08 | 项目与任务详情 | 邀请、接受、调整条件、报告结果、核验 |
| UI09 | 个人复盘与共同复盘 | 保存私稿、选择摘录、生成调整草稿 |
| UI10 | 共同记忆与发布审核 | 浏览经验、写感谢、审阅授权、撤下 |
| UI11 | 我的权限与求助 | 查看分享、撤权、申请导出、更正和求助 |
| UI12 | 运营与维护后台 | 材料审核、角色管理、请求处理、服务与恢复 |

### 操作和反馈

任何共享、批准、接受任务和导出操作，在按钮附近说明对象、受众及后果。低影响编辑允许自动保存；改变他人可见范围或正式状态的动作必须显式提交，成功后显示服务器确认的记录。禁止用同一个“确认”按钮承担多种效力。

通用状态包括加载中、空记录、待本人处理、权限不足、版本变化、连接中断及 AI 不可用。错误信息给出可继续的动作；权限错误不透露被禁止对象的标题、作者或是否存在。重要错误不只依赖颜色表达。

### 可及性与公共终端

普通正文建议至少 16 像素，主要点击区域不小于 44 像素；200% 放大后主要流程不丢失操作。表格在手机端转为同字段的逐项比较卡，完整原话和异议不能因折叠而消失。功能支持键盘操作、可读标签和明显焦点。

公用终端使用单次会话，退出或闲置 5 分钟后清除本地页面数据并返回登录页；提醒用户未提交内容尚未保存。公共屏使用独立展示会话，禁止从个人账号直接镜像投放整个浏览器。纸面模板保留与数字记录相同的字段及编号。

## 06 核心功能规格

### F01 本地账号与参与入口

管理员创建一次性邀请，成员设置个人凭据和显示称呼；除确有用途外，不要求填写完整身份背景。账号绑定独立成员标识，允许名称变更而不改写历史操作人。首期邀请有效期建议 7 天，首次使用后失效；管理员操作启用本地可用的多因素认证与恢复码。

成员登录后看到本人可访问的资料和待回应事项。退出社区、暂停账号与删除资料是不同操作。冻结账号立即使服务端会话失效，但不自动取消既有任务或删除公共决定；协调人按实际情况处理交接。

验收 F01：过期邀请无法使用；普通成员不能自升权限；冻结后的既有会话不能继续读写；断开互联网并重启后仍可登录；公用终端退出后下一位不能回看前人的内容。

### F02 社区知识查询与新成员引导

搜索结果先显示资料标题、类型、有效状态和维护人。问答卡先给简短回答，再列可定位的依据与“查看原文”“提出纠错”“联系负责人”。旧规则标注已失效并指向现行版本；来源冲突时说明冲突，不能替负责人选择哪份规则生效。

查询任务状态、成员权限和现行决定时，通过已授权的业务查询读取当前记录。文档检索只补充背景。没有依据时明确说明“目前没有足够资料回答”，并提供人工路径。界面不得用生成的编号或链接伪装真实引用。

新成员可选择一条短引导：了解社区、查看参与规则、认识项目、找到联系人。用户可以跳过和退出。询问如何参加项目只能生成参与申请草稿，发送前再次预览，不能直接加入小组或占用资源。

验收 F02：点开引用能看到获准原文的对应片段；无权资料不出现在结果、数量、摘要与引用中；过期文档不会被当成当前决定；AI 停机时目录和关键词检索继续可用。

### F03 帮助表达与转述确认

输入区先保存成员原话，背景与用途为可选说明。用户主动选择“帮我说清楚”后，系统生成最多两种候选文本，分别说明保留了什么、哪里需要本人补充。候选文本标记“待本人核对”，与原话相邻显示。

用户可以选择“这版准确”“我来修改”“只用原话”“放弃转述”。保存准确版本后，另一步选择受众与用途，完整预览本次共享文本。原话与转述分别设置共享选择：允许分享转述而不分享原话，默认不附带私人背景。原始稿始终由作者回看。

转述必须保留原话中的立场、拒绝、条件、责任归属、不确定性及作者希望保留的语气。例如“这个安排我不能接受，也不会参加”，不得被改成“我有些担心，但愿意配合”。改善表达不能把真实冲突消解为表面同意。

任何正文修改都会生成新版本；旧确认继续作为旧版历史，不能自动适用于新版。已提交议题的观点变更，显示新旧差异并提示主持人更新摘要。未发布内容可直接删除；已进入正式流程的表达按撤回和更正规则处理。

验收 F03：确认准确不会自动分享；分享时只发送预览内字段；作者拒绝转述后不影响参与机会；修改一字后的新版本也不能继承旧确认；主持人不能读取没有获准分享的原话。

### F04 核对理解与共同词义

阅读他人观点时可选“请帮我理解”，获得日常例子和待询问问题。解释只标记为 AI 帮助，不冒充作者立场。读者填写“我理解的是……”后，选择是否向作者发出核对请求。作者可回应准确、需要修正或希望当面交流；部分准确时进入需要修正，标出准确部分和需要补充之处。

“准确理解”只改变核对记录，不改变对方案的支持状态。请求中的私人解释默认仅双方可见；向议题展示需另行共享。共同词义以议题内条目保存不同解释、例子、暂用定义及适用范围，保留未达成一致的含义。

验收 F04：作者的回应绑定复述和原观点版本；原观点变更后显示需重新核对；核对准确不增加支持人数；未经分享的双方交流不进入主持摘要。

### F05 议题发起与方案比较

提出者填写问题、受影响者、讨论范围、现有材料、可用资源、时间约束及希望如何决定。主持人核对批准权限与参与机会后开放讨论。首版支持“已登记批准者逐人批准，并满足指定前提”的流程；需要正式表决的议题先在线下按既定程序完成，系统登记过程与证据，不推断票数或法定有效性。

议题页分为概况、观点、方案、分歧、决定五区。观点只能使用作者主动提交的原话或已确认的转述。每个方案按时间、费用、劳动、资源、风险、停止条件比较；未核实项明确标记。可以保留“暂不行动”方案，无法继续时记录原因。

成员可对具体方案表达支持、有条件支持、保留、反对、需要了解。条件必须具体记录；未回应始终单列。立场绑定方案版本，方案更新后原立场仅作为历史显示。立场分布用于理解讨论，不自动触发批准。

验收 F05：未核对的 AI 转述不能成为正式观点；摘要必须保留实质异议和未核实项；改变方案后不能把旧支持复制为新支持；主持人不能删除他人异议，只能回应、请求澄清或按程序限制展示并留痕。

### F06 现场议事与公共屏

主持人从已获准材料中选择当前议程、观点或方案，先看到公共屏预览，再执行展示。公共屏有独立受众范围和短时展示凭据。首版规定：获准在当前会议展示的内容，视为已允许该场会议在场受众看到；主持人开场核对在场范围，出现额外受众时暂停并重新选择材料。

每轮讨论后，主持人可请求生成摘要草稿，人工检查原话、异议和依据，再发给相关成员核对。未确认记录带状态展示，不能排版成已达成的决定。讨论结束由主持人结束投屏，展示凭据失效并清屏。

验收 F06：私人草稿不能被投屏接口读取；获准手机查看不等于获准投屏；主持人切换页面不会把私人内容带到公共屏；撤回展示授权后公共屏在下一次校验时清除，目标不超过 5 秒。

### F07 决定核对与批准

决定草稿包含已经约定的事项、尚有分歧、试行事项、未参与或未回应者、执行条件与重议触发条件。保存批准规则快照、材料版本、成本边界、试行期限和复盘日期。页面分别提供“我的意见记录准确”“表达我的立场”“按授权批准本决定”，按钮与说明不得合并。

进入待批准前，主持人提交参与机会、关键异议、必需条件与规则核对清单。每位必需批准者对同一决定版本操作；规定需要当事人单独同意的条件，须有对应记录。所有条件齐备后，业务服务在事务内改变决定效力。模型只能写草稿，不能拥有批准凭据。

进入待批准时冻结批准人标识、规则版本和决定版本。最终生效事务重新检查全部必需批准及批准者当前资格；有人在生效前被冻结、失去资格或被替换时暂停批准，由有权主体确认新规则或新版本并重新完成该版批准。已生效决定不因批准者后来离任而自动失效，涉嫌无效的批准按复核或撤销流程处理并保留历史。

必需条件保存为独立记录，包含条件编号、类型、适用版本、责任人、是否必需、状态、证据及确认时间。决定生效前提与项目开始前提分开：前者包括指定批准与必要同意，后者包括关键任务接受和资源确认。只有明确标记必需的条件进入程序判断，AI 不能凭说明文字宣布条件满足。

新版本不覆盖已生效旧版本。新版本完成核对和批准后，旧版标记被取代；新草稿产生期间旧版是否继续有效，由原决定的暂停条款处理，不能默认失效。存在疑义时允许有权者暂停执行，保留批准历史。

验收 F07：缺少必需批准者时不能生效；旧页面提交遇到新版本时拒绝并显示差异；批准记录不能被普通编辑覆盖；决定有效但关键任务尚未被接受时，项目明确显示“尚不具备开始条件”。

### F08 行动约定与任务承诺

项目页说明目标、受益者、最小尝试、资源上限、负责人、参与办法与复盘日期。任务详情显示事项、完成标准、承担者、期限、依赖、工具、费用、报酬或自愿性质、结果核验人。AI 拆出的任务首先进入建议区，协调人选择后才能发出邀请。

受邀者可接受、提出条件或拒绝；只有接受才形成任务承诺。采用纸面接受时，代录人附确认方式和凭据，记录“本人线下接受，由某人录入”，不能伪装成账号本人点击。资源由负责人登记确认凭据，不因任务生成而视为已获得。

任务邀请单独保存待回应、待协商、已接受、已拒绝、已撤回和已到期等状态。拒绝或到期只结束本次邀请，并从本人待回应列表移除，不取消整个任务。协调人可提出新邀请；修改条款后须新建邀请，旧结果保留。每项任务首版只设一位主要承担者，额外协作以独立任务或明确的协作邀请处理。

承担者可报告受阻或提出变更。待变更期间保留旧约定及其是否暂停的明确状态；经承担者和协调人确认后新条款生效，预算或资源批准受影响时补齐相应批准。任务完成由事先登记的核验人核对，核验退回需要说明差异与下一步。

验收 F08：未接受任务不显示为已承诺；拒绝不扣分、不触发公开评价；改期限、报酬或完成标准后需重新确认；重复点击接受只产生一次有效事件；暂停和取消有明确处理人及理由。

### F09 个人复盘与共同复盘

任务或试行到达复盘点后，系统邀请参与者自愿反馈实际结果、与约定的差异、有效做法、困难和下一步建议。个人先在私人区域保存，再选取愿意共享的段落和受众。协调人仅能汇总已授权摘录。

共同复盘区分事实、个人体验和解释，形成行动调整与经验草稿。行动调整重新进入相应任务或决定的变更流程；复盘摘要本身不能修改已批准预算或成员承诺。未反馈成员不被推断为满意。

验收 F09：私人复盘不进入小组摘要；共享摘录与私稿分别存储和授权；复盘提出的新任务保持待接受；不同体验可以并列保存，不以多数反馈删除少数记录。

### F10 共同记忆与情感表达

共同记忆采用按项目、地点和时间浏览的经验册。条目类型包括方法经验、社区故事与具体感谢。经验记录问题、尝试、结果、适用条件及未知事项；故事区分真实经历、改编与虚构；感谢说明具体的人和事，由作者选择私下分享、小组分享或社区分享。

发布页展示待发布的准确文本、署名、受众、用途、保留安排及涉及的人。相关人按条目版本和用途确认；缺少任何必需授权时保持待授权。可通过删去可识别内容形成新稿，但新稿仍需人工判断和对应审核，不能仅由模型宣称已匿名。

作者申报可识别涉及者，审核人核对正文、署名及相关素材后确认必需授权清单。模型只能提示可能遗漏的人，不能作最终判断。有人报告遗漏本人、误署名或超出用途时，先暂停相关内容展示，再由受理人核对，不能因列表内其他人已经同意而直接放行。

首期发布仅面向本地服务内获准对象。公开展览、外部媒体或互联网转载属于新用途，需重新办理，不继承内部分享授权。感谢不要求回应，不统计为声望或投票权。

验收 F10：多人授权不齐无法发布；调整文本、受众或用途后重新审核授权；撤下后目录、检索、引用和后续生成停止使用；不能承诺收回他人已获得的线下副本。

### F11 人工帮助与程序异议

每个议题、任务和个人页面提供“找人协助”。成员选择普通协助、记录纠错、程序异议或只请求联系，指定已公布的受理人。提交前预览文本与可见范围，可不填写私人经历。涉及主持人的异议可选择独立联系人。

工单显示已提交、已接收、处理中、等待本人补充、已处理或本人撤回。建议两个工作日内确认收到，五个工作日内说明处理路径；无法完成时更新下一次回应时间。时间提醒只反映处理状态，不自动裁决争议。

验收 F11：被申诉者不能因主持角色自动读到请求；改派受理人前说明新受众并取得相应用途授权；只有请求者主动分享时，求助内容才进入其他业务对象。

### F12 个人权限与运营管理

成员可查看自己正在分享什么、分享给谁、用于什么及何时到期，并选择缩小范围、撤回、申请更正、导出或删除。页面分别说明对当前可见性、正式历史与备份的影响。发起个人导出时预览包含类别，输出不得混入他人私有内容。

后台按资料审核、议事维护、账号权限、请求受理及运行维护分区。管理员看到自己职责内的待办，不使用一个默认可见全部内容的超级业务角色。AI 总开关和分模块开关关闭后，既有记录、人工录入、批准、接受任务与导出继续工作。

验收 F12：收紧权限后下一次服务端访问即按新策略处理；导出包记录生成时间和范围并限制领取；恢复备份后先恢复撤权和删除状态再开放访问；两名接管者能分别按文档完成关键操作。

## 07 状态模型与不可混淆的确认

### 分开保存五种事实

表达准确性、分享授权、方案立场、决定批准和任务承担是独立事实，不能压缩为一个 confirmed 字段。成员点击任一动作，只改变该动作对应对象。系统用稳定事件名称记录 actor、object、version、time 和 effect，便于界面与验收逐项核对。

| 对象 | 主要状态 | 关键转换条件 |
| --- | --- | --- |
| 表达版本 | 私人草稿、待核对、已确认、被新版替代、已撤回 | 本人或注明凭据的线下确认；分享另设授权 |
| 理解核对 | 待回应、准确、需修正、转线下、已关闭 | 作者回应指定观点及复述版本 |
| 议题 | 草稿、讨论中、待决定、行动中、复盘中、已归档 | 主持人按阶段条件推进；可暂停或结束 |
| 决定 | 草案、征询中、待批准、已生效、被取代、已撤销 | 当前版本的必需批准和条件齐备 |
| 任务 | 建议、待接受、已接受、执行中、待核验、已完成、已取消 | 邀请结果独立保存；核验人确认完成 |
| 任务邀请 | 待回应、待协商、已接受、已拒绝、已撤回、已到期 | 接受绑定具体条款；拒绝不取消整个任务 |
| 记忆条目 | 草稿、待授权、待审核、已发布、已撤下 | 当前版本的必需授权和发布审核齐备 |
| 资料版本 | 待审核、解析中、待关键词索引、已发布、已失效、已撤下 | 审核与基本检索就绪后发布；向量状态独立保存 |

“受阻”“提出变更”“执行暂停”分别作为附加状态或独立申请，不无限扩展主状态。议题处于讨论中时，可以存在已经批准的小试验；不能用议题总状态覆盖每份决定的真实效力。已完成任务的纠错以追加记录处理，不直接擦除完成历史。

### 版本与并发

所有关键写入提交当前版本和幂等键。服务端核对权限、状态、对象版本及相关授权后，在同一事务中写入业务记录和审计事件。版本不一致返回可恢复冲突，用户看到变化后重新提交；同一幂等键、相同内容返回原结果，不再次批准或接受。

新增版本与原确认绑定关系不可混用。原文更改、方案更改、任务条款变化或记忆用途扩展，均对新版本重新执行相应确认。已确认旧版保留历史标签。授权撤回立即影响后续访问；索引清理可以异步，但不得造成等待清理期间继续泄露。

## 08 数据对象与访问规则

### 最小数据模型

| 数据对象 | 必备字段或关系 | 约束 |
| --- | --- | --- |
| Member 与 RoleGrant | 成员标识、显示名、账号状态、角色、作用范围、期限 | 身份与社区角色分开；到期和冻结实时检查 |
| AccessGrant | 对象或版本、受众、用途、期限、授予人、撤销时间 | 分享范围不能仅存在提示词中 |
| Utterance 与 Revision | 作者、原话、版本、背景、确认事件、选定转述 | 原话与转述共享选择分别存储 |
| UnderstandingCheck | 观点版本、读者复述版本、作者回应 | 只表示理解是否准确 |
| Topic 与 Option | 范围、参与者、规则快照、方案版本、立场、异议 | 立场关联方案版本；未回应显式表示 |
| Decision 与 Approval | 内容版本、必需批准人、条件、批准、效力、取代关系 | 不覆盖已生效内容；批准不可由模型生成 |
| Project 与 Task | 目标、资源、条款版本、承担者、接受、核验、变更 | 受邀者不自动成为承担者 |
| TaskInvitation 与 Condition | 受邀者、条款版本、回应；条件类型、适用版本、责任人、证据、状态 | 邀请与任务独立；生效条件与开始条件分开 |
| Review 与 SharedExcerpt | 私人复盘、共享摘录、来源版本、受众 | 汇总只能使用获准摘录 |
| Memory 与 Consent | 类型、正文版本、涉及者、用途、授权、审核、发布 | 授权必须覆盖实际文本和受众 |
| Document 与 Chunk | 原件、来源、版本、有效期、授权、片段位置、索引版本 | 片段不得自行扩大原件权限 |
| HelpRequest 与 DataRequest | 申请人、类型、受理人、状态、期限、处理记录 | 限定请求级访问 |
| AIJob 与 AuditEvent | 发起人、用途、输入对象版本、权限版本、状态、模型配置、操作证据 | 默认不留完整敏感提示词和推理内容 |

所有业务对象带创建时间、更新时间、创建人及社区标识。服务端保存 UTC 时间，界面按社区时区显示。附件原件与对象绑定，下载重新鉴权。正式记录的内容、版本与操作事件使用事务保证一致，不能以可编辑聊天记录代替批准凭据。

原话版本、转述版本和私人背景分别具有可鉴权标识；同属一条表达不意味着访问权自动继承，接口只序列化获准字段。创建私稿时建立作者访问权。用途由服务端按接口和批准规则确定，客户端填写用途不能扩大权限。

### 权限判定

访问同时满足账号有效、角色允许当前动作、对象授权覆盖当前成员、用途符合且授权未过期。授权按对象细分；同一成员能读取议题，不代表能读取其所有关联私人草稿。页面、搜索、生成上下文、引用、附件、导出和公共屏都执行同一规则。

汇总多个来源时，系统只用当前请求人和目标受众均获准的材料。不能将主持人个人能看的资料汇总后展示给全体。模型输出保留来源关系，来源撤权后，仍依赖该来源的派生草稿停止展示并提示重新生成；经独立授权发布的正式记录按其自身保留和更正规则处理，不能简单删除整份公共决定。

作者确认并独立授权分享的转述，可以作为单独的共享对象，接收者不因此获得原话或私人背景的读取权。系统内部保留必要的版本关联，接收页面只显示其有权知道的确认状态。历史版本继续受当前访问政策控制，保留历史不意味着永久向所有人公开。

应用连接使用非超级用户，行级策略作为额外防线。PostgreSQL 文档说明高权限角色及部分表所有者存在绕过行级策略的情形，因此上线需检验实际连接身份与策略效果，而非仅检查是否开启配置。[S3]

### 五项 AI 服务

| 服务 | 允许输入 | 输出及验证 |
| --- | --- | --- |
| 有依据的问答 | 已授权检索片段或业务只读结果 | 简答、来源标识、未知项、人工下一步；来源必须真实存在 |
| 表达辅助 | 用户主动选择的原话与本次背景 | 不超过两种转述、待核对问题；不得新增人物动机 |
| 理解辅助 | 获准观点与读者自述语境 | 通俗解释、例子、澄清问题；不代作者确认 |
| 协商整理 | 已共享且适合目标受众的观点和方案 | 共同点、差异、事实待查、异议及来源；无自动共识结论 |
| 行动与复盘拟稿 | 已授权决定、任务及共享摘录 | 待确认任务或经验草稿；不执行正式写入 |

输出通过预定结构校验后，仍展示为草稿。来源缺失、格式错误或内容超范围时，不做正式保存；保留用户输入并允许重试或手工处理。模型不得访问管理员凭据、自由执行命令、直接发送消息或改变业务状态。

### 资料入库

首期接受 UTF-8 文本、Markdown、DOCX 和带可提取文字的 PDF，建议单文件上限 20 MiB、PDF 最多 100 页；扫描资料显示“需要人工整理”，不承诺自动 OCR。图片附件、录音与复杂表格解析在后续单独验收。

维护人检查来源、权利、用途、可见范围、有效时间和维护责任后送入隔离解析。完成审核、文本提取及关键词索引后可供授权查阅和基本查询；向量化另设状态，失败可重试，不阻止基本发布。只有向量索引就绪的版本进入语义检索。重试不得产生重复有效版本。

### 检索与来源

先确定获准资料范围，再检索可返回片段。首期材料量较小时优先检验带权限过滤的精确向量检索与中文关键词检索，必要时再使用近似索引；pgvector 的近似索引过滤行为会影响返回条数，扩容时必须检查召回效果。[S2]

中文分词和别名表本地处理，以开发问题集调整分段、召回和上下文长度。来源卡展示文档名、有效版本、位置及短片段；来源无权或已撤下时不返回原文。更换向量模型需要重建索引，期间保留已验证的关键词路径。

### 权限变化与生成任务

AIJob 保存使用的对象版本和权限版本。开始生成前和返回结果前分别校验；生成期间发生撤权、来源更改或取消，则丢弃待展示结果并说明需要重试。首版私有内容的生成不边生成边外发，以便完成返回前检查；界面显示准备、生成、校验等进度。

所有查询和回答缓存按用户、用途、对象版本与权限版本隔离。权限收紧立即使相关缓存不可命中，物理删除后台完成。已被成员阅读或另行复制的内容无法技术性收回，界面和授权说明必须讲清这一限制。

### 模型选择与评测

首版通过可替换的本地模型适配层接入推理服务。Ollama 可作为首测运行器，启用本地模式并配合出口限制；官方文档提供 OLLAMA_NO_CLOUD 配置，但断网能力仍须覆盖整套应用验证。[S1]

基础模型先比较中文表达与结构化输出表现，具体模型、量化、上下文上限在开发样本测试后冻结。沿用既有方案的中文模型候选方向，不把参数量或新旧当作采购结论。80 条开发样本可用于改进提示和检索；200 条独立验收样本不得提前用于调优。模型和提示模板升级都需回归测试。

## 10 开发架构与接口约定

### 本地单节点架构

首版建议沿用 TypeScript 与 Vue 的手机网页、Python FastAPI 模块化应用、PostgreSQL 与 pgvector、本地文件存储和独立模型进程。技术栈为工程基线，确切依赖版本在建仓时锁定。使用简单容器编排和后台作业，不引入微服务集群及分布式知识图谱。

浏览器只连接应用网关；应用负责身份、权限、流程和输入校验。数据库保存业务事实，文件区保存原件，后台作业负责解析、索引和生成。模型返回候选内容，业务服务决定是否能展示；正式状态只能由经过授权的业务接口改变。

开发模式允许使用合成资料和确定性 AI 替身，以便先实现交互与测试，但替身必须明显标注且不能计入模型质量验收。真实资料只在批准的本地环境使用，不上传到 GitHub、云端开发日志或外部模型。

### 接口形状

所有业务接口以 /api/v1 为前缀。认证使用服务端会话及安全 Cookie，跨站写请求校验防伪令牌；本地 HTTPS、可信证书和账号恢复必须纳入部署包。页面不得直接访问数据库和模型端口。

| 接口示例 | 行为 | 正式写入条件 |
| --- | --- | --- |
| POST /utterances | 保存个人表达草稿 | 本人身份与输入校验 |
| POST /ai-jobs | 请求问答、转述或摘要 | 只读授权范围与用途检查 |
| POST /utterances/{id}/confirmations | 确认指定表达版本准确 | 作者或有凭据的线下代录；不自动共享 |
| POST /access-grants | 共享具体对象及用途 | 分享人有权授予该范围 |
| POST /understanding-checks | 向作者提交复述核对 | 双方能访问相关观点版本 |
| POST /topics/{id}/stances | 提交方案立场 | 参与资格及方案版本有效 |
| POST /decisions/{id}/approvals | 批准指定版本 | 必需批准角色、规则与前提条件 |
| POST /tasks/{id}/acceptances | 接受具体任务条款 | 本人或有凭据的线下接受记录 |
| POST /memories/{id}/publication | 发布记忆 | 版本授权齐备及审核通过 |
| POST /data-requests | 提交个人数据请求 | 请求者身份及可申请范围 |

路径是开发约定，完整请求与响应以仓库中的 OpenAPI 定义为准。关键请求包含 object_version、idempotency_key，确认类请求再包含 action 和 payload_hash。服务端重新计算内容摘要、核对身份与版本，不能信任客户端自报批准人或权限。

### 错误与重试

版本过期返回 409，并在调用者有权访问的前提下提供新版本信息；业务前提不满足返回 422；没有权限的对象按统一不可用响应处理，避免透露存在性；服务忙返回可重试状态和等待提示。重复请求不能生成重复操作事件，同一幂等键对应不同内容必须拒绝。

首版不做终端离线自动同步。局域网断连时保留当前页面未提交输入并提示尚未保存，关键批准与接受按钮停用；恢复连接后先取回服务器版本再提交。一般终端默认不将私人草稿持久化在浏览器存储，公共终端更不得保留敏感缓存。

## 11 非功能要求与运行边界

### 容量与性能目标

| 指标 | 首期验收目标 | 固定测试条件 |
| --- | --- | --- |
| 参与规模 | 20 至 40 名注册试点成员 | 单社区、约 20 人普通业务同时在线 |
| 资料规模 | 100 至 300 份获准材料 | 同时记录片段数、原件总量与最长文档 |
| 普通业务响应 | P95 不超过 1 秒 | 本地网络，单页 50 条以内，不含文件传输 |
| 资料检索 | P95 不超过 2 秒 | 固定资料集与权限过滤，冷暖缓存分别报告 |
| AI 生成 | 队列外完整校验结果 P95 不超过 45 秒 | 热模型，最多 3 路生成，输入不超过 8 千 token，输出不超过 300 token |
| 生成排队 | 显示排队、可取消，等待超过 60 秒给出重试或手工路径 | 排队时长单独记录，不计入纯推理时延掩盖等待 |
| 撤权生效 | 下一次服务端请求即阻止新访问 | 覆盖页面、下载、检索、缓存和任务返回 |
| 恢复 | 业务 RPO 24 小时，基本记录 RTO 4 小时 | 备份完好且已有可用备用环境；模型另测 |

以上为目标，不是现有设备实测承诺。完整发布前记录设备、模型、量化、负载和语料配置。手机长文、长输出和语音不混入普通问答指标。考虑首版返回前权限校验，交互验收以完整结果及进度反馈为准，不沿用边生成边显示的首字指标。

### 网络和故障

离线可用指外部互联网断开，但本地电力、局域网、服务器可用。模型、前端资源、字体、身份服务和依赖包预先准备；断开外网并重启后测试完整流程。手机离开局域网不继续访问本地服务，停电也不保证运行。

模型失败时保留目录、关键词搜索和全部人工业务。数据库或授权服务不可用时，停止需要鉴权的读写，不能用陈旧权限缓存继续服务。公共屏失去服务端心跳超过 10 秒时清屏，恢复后重新校验展示内容。

### 备份与接管

每日备份业务数据、原件和配置，定期轮换离线介质。模型、依赖包、许可证、校验值和构建说明一并交付。恢复先在隔离环境完成，再重放备份时间点之后的撤权与删除记录；缺少可靠记录时保持隔离，人工核对后再开放。

撤权与删除清单须在操作确认成功前写入独立持久介质或等效受保护存储，不能与每日备份一起回退。若该写入失败，界面明确标记删除或撤权尚未完成，先在现运行服务收紧访问，再告知受理人处理。备份保留建议 30 天，具体周期由责任主体确认。

权限收紧日志使用连续序号和完整性校验，包含账号冻结、角色撤销、受众移除、发布撤下与删除。备份记录对应序号，恢复核对后续事件连续且覆盖独立保存的可信最新序号。缺少可信序号、出现中断或恢复日志不完整时保持隔离，不能仅因日志文件可读取就通过恢复验收。

## 12 保留退出与发布规则

### 数据最小化

普通问答默认不长期保存，用户主动保存时建议保留 30 天；未确认私人草稿 30 天后提醒清理，不能未经告知自动公开；正式项目和决定按用途定期复核。安全审计只保存必要操作证据，试点规划 180 天，实施时另核对适用要求。语音尚未进入首版，不提前建立声音档案。

不采集用于人物画像的点击流、亲密关系、情绪趋势和隐性信任网络。为了服务稳定，可记录不含正文的请求时长、失败类型和队列长度。调试若需完整样本，应单独授权、限定范围和期限，并在可控本地环境进行。

### 退出与数据请求

成员可暂停使用、退出参与、撤回分享或提出删除申请。退出不等于自动删除他人的合法记录；任务退出应进入交接或取消流程。系统逐项说明可立即停止的访问、需要处理的共同记录及备份清除期限。

个人导出采用可读文本与结构化 JSON，并附已获准提供的附件清单；共享项目导出由有权者发起，仍逐条过滤个人隐私。导出文件建议 24 小时后失效清理，领取再次鉴权，不以可长期转发的裸链接提供。

### 面向真实使用的前置条件

社区需确认责任主体、批准者与替补、试点议题、参与说明、受理渠道和保留规则。敏感医疗、严重冲突以及未成年人资料不作为首期普通知识资料入库。若将来面向公众提供生成式服务或扩展外部发布，另行核查适用义务、内容标识、处理依据与必要评估，不能以本地部署推定免除责任。

## 13 验收规格与试点评价

### 测试分层

状态与权限测试覆盖确定性规则，端到端测试覆盖实际用户路径，模型测试检查依据、转述与异议保留，试点观察评估人是否真正能理解和控制操作。权限红线和正式授权错误不与模型平均分相抵。

沿用 80 条开发样本及独立 200 条验收样本：知识问答 80 条、表达翻译 40 条、协商记录 30 条、权限与安全 30 条、行动及数据请求 20 条。除固定集外，对权限矩阵、并发和状态边界生成专项测试，不能用 30 条安全题宣称穷尽风险。

知识问答建议至少 72 条整体可接受、76 条来源正确；表达翻译至少 34 条首稿可接受，所有发布版本均有本人确认；协商测试中关键异议和批准信息不得遗漏。两个评审核对，有分歧时第三人复核。正确拒答或说明资料不足可以通过，伪造来源、泄漏隐私或制造共识直接不通过。

### 可用性与关系体验

邀请至少 8 位不同数字熟悉程度的试用者，完成查资料、表达并选择受众、核对理解、接受或拒绝任务、提出纠错、撤回分享六项任务；其中至少两位通过纸面或协助参与。记录完成情况、卡点、误解和协助类型，不对个人排名。目标为至少 7 位能在允许的协助下完成自己的适用路径，所有人能说明分享给谁以及如何求助。

在两轮真实协商中，征求自愿反馈：自己的意思是否准确呈现、是否能表达不同意见、是否理解决定依据、是否清楚承诺与变更办法。回访关注发生了哪些实际变化，并记录失败和不适用情形。小群体不公布容易识别个人的分组结果；关系评价不设自动得分闸门。

## 14 开发任务与团队安排

### 建议团队与工作顺序

技术主力按一名前端、一名后端与 AI 工程师配置，产品与社区运营持续参与，测试及接管复核独立安排。产品负责人负责范围和规则清晰，社区授权者负责真实批准程序，开发人员不替社区决定谁具有治理资格。

先完成权限、版本及人工流程，再接入 AI。这样每次模型生成都有确定的对象、用途和确认动作，模型暂时不可用也不妨碍验证产品。界面与后端共同以同一组用户故事和 AT 编号验收。

| 工作包 | 主要范围 | 前置依赖 | 完成凭据 |
| --- | --- | --- | --- |
| EP01 工程基础 | 仓库结构、开发环境、配置、合成样本、构建 | 无 | 新环境按说明启动，依赖锁定 |
| EP02 身份与授权 | 本地账号、角色、对象授权、审计 | EP01 | F01 与 AT20 通过 |

### 首个两周的开发输出

第一周完成仓库、页面导航、本地登录、对象权限和版本基础，以合成的场地工作坊场景贯通创建议题与个人草稿。第二周完成手工表达核对、方案立场、任务邀请与接受，补齐错误、重复提交和旧版本冲突。AI 可先使用明显标识的替身接口。

R0 的任务邀请在无真实决定效力的合成项目中单独验证；R1 接入 EP05 的决定批准和资源开始条件后，才验收完整行动过程。这样首轮无需等待决定模块全部完成，同时不把演示中的接受记录作为真实执行依据。

第一轮演示必须同时展示正常路径和拒绝路径：不分享原话、不同意方案、拒绝任务、无权读取和模型关闭。研发结束时提交可运行代码、测试结果及已知缺陷，不能只提供截图。涉及真实决定批准的阶段，在规则配置与相应验收完成后才开放。

### 工期与预算处理

首期仍以 90 天试点安排，工时和设备费用需根据实际团队报价及模型测试更新。既有方案约 21.30 万元试点和 29.18 万元首年投入属于历史规划测算，本产品书不将其重新定义为报价或承诺。需求冻结后将工作包拆到 1 至 3 天可完成的任务，再形成真实排程。

## 15 GitHub 协作与交付规范

### 建议仓库组织

建议使用一个社区控制的私有仓库 gongrang-community-brain，后续如需开源，再检查许可、凭据与资料范围。默认分支保存可运行基线，功能通过短分支和 Pull Request 合并。仓库所有权、管理权限和恢复渠道归社区指定账号或组织控制。

### 合并与完成标准

功能完成必须包含实现、与风险相称的测试、涉及的权限和错误状态、必要文档及人工演示。权限、确认、批准和发布变更需要独立复核。生成界面演示不等于后端规则实现；测试通过不等于真实社区批准。

PR 描述说明解决什么问题、改变什么行为、对应 F 和 AT 编号、如何验证、迁移与回滚影响。自动检查失败时不得以文档标记完成。依赖或模型更新需记录许可、校验值及输出回归结果。

### 独立接管验收

交付源码、提交记录、可重建包、离线依赖、模型清单与校验值、账号控制权、配置与密钥移交办法、数据字典、接口文档、测试证据、运维手册和培训记录。按清单逐项签收，遗留事项写清责任人与期限。

最终演练由两名社区接管者分别完成：从交付包部署或恢复，新增与冻结账号，审核资料，纠正记录，导出项目，关闭 AI，再按文档恢复。操作过程不依赖原开发人员口头补充。

交付后的目标是社区在约定边界内能够独立运行，或自主更换维护方。所有必需外部依赖、许可期限、费用、账号归属和替代方案明示；开发方个人账号、未披露服务或无法取得的构建条件不能成为持续运行的障碍。

## 16 实施决策与后续演进

### 可以立即开始的工作

以合成数据开始页面与权限开发，采用单社区本地部署、六个入口和十二项功能规格。先建立人工流程的完整性，再接模型；按本产品书 AT 案例同时编写端到端测试。完成第一轮后用真实使用者反馈调整文字、步骤和帮助方式。

### 真实试用前必须落实的事项

| 待落实事项 | 建议责任人 | 对开发的影响 |
| --- | --- | --- |
| 社区责任主体与接管账号 | 项目发起人 | 决定仓库、设备及数据控制权 |
| 首期议题及受影响者 | 社区协调人与主持人 | 确定招募、程序和页面样本 |
| 批准规则及批准者替补 | 有权决定主体 | 配置批准条件；未明确前仅测试 |
| 数据范围与保留安排 | 数据负责人及成员代表 | 决定资料入库、撤权和导出政策 |
| 本地主机、网络、备用条件 | 技术维护人与采购人 | 决定并发、性能和恢复目标 |
| 真实运营与缺陷响应人员 | 项目负责人 | 决定开放时段和能维护的功能 |

这些事项不妨碍合成数据开发，但不能由程序中的默认值代替社区真实授权。每项决策记录日期、适用范围、批准依据和复核时间，改变后检查受影响的页面、流程与测试。

### 长期产品方向

共壤智脑可以逐步连接地方观察、实践学习、艺术表达、生计协作和社区互助。共同原则是让人们理解彼此的处境、共同尝试、对后果负责，并自主决定哪些经验值得留下。后续每个模块须有具体使用者、真实场景和可维护的最小流程。

系统的成熟度通过可持续参与和独立运作体现。若某个功能需要不断收集私人生活才能成立，或让成员不敢反对、不敢退出，就应重新设计。若一个简单的资料页、一份清楚的行动约定或一次线下对话已经足够，产品应支持这种选择。

### 术语

PRD 指产品需求文档。F 编号标识功能，UI 编号标识页面，AT 编号标识验收案例，EP 编号标识开发工作包。RAG 指先检索获准资料，再由模型依据资料回答。幂等指同一请求重复提交不会产生重复有效操作。RPO 表示可接受的数据损失时间范围，RTO 表示恢复服务的目标时间。

“确认”必须具体说明确认的对象和效力；“共识”只用于有凭据的同意范围；“本地”说明实际计算与数据边界；“共同记忆”指经过选择和授权留下的经验，不包含默认收集的个人生活档案。
