## 2. 本轮承接的产品目标

原方案第 01、04、07 章将“可确认的翻译、可追溯的协商、有限承诺与共同复盘”放在产品中心。R0.2 先补齐其中一段能够实际操作的关系支持流程：成员保留自己的原话，选择如何转述，决定是否分享；听者用自己的话复述，再请表达者核对。软件只记录这些明确行为，不推断未表达的动机，也不把理解准确换算成赞同、承诺或信任评价。

本轮完成标准是上述流程及其拒绝、修改、撤回和越权边界经过验证。成员是否更愿意相互信任，仍须按原方案第 14 章通过真实行动、自愿反馈和人工观察评估；开发环境中的流畅文字和合成账户操作不能代替这种评价。

## 4. 转述与理解核对的交互约定

### 4.1 原话、候选、当前选择各自有版本

成员先保存并核对自己的原话，再按需编写候选。候选所需的背景、面向何种语境及本次用途由本人主动提供，可以留空；这些字段不是许可系统，也不让接收者取得更多内容。系统不从历史私聊、身份、职业或年龄补齐背景。

选定候选时，确认它准确表达了本人的意思；随后另行预览分享。选择“仅保留原话”或“不允许转述”时不要求接受任何候选，不减少参与机会。“不允许转述”表示当前候选不被认可，不能被解释成用户永远失去修改选择或主动请求私人建议的权利。

原话改写使旧候选和选择失效；已确认候选改写或当前选择改变时停止现有分享。旧版本存在于历史或数据库中，不意味着可继续作为当前观点公开。重复请求也不得使已撤回的内容重新出现。候选采用 `manual` 或 `local_model` 标记来源，个人修改后按合同标为手工版本，不把手工文字冒称模型原始输出。

### 4.2 分享的是预览中的单一表达

分享窗口应说明即将发布的是原话还是已确认转述，以及哪些议题成员会看见。接收者只能读取已分享正文、作者称呼、来源版本和确认状态，不取得私人原话、背景、用途或其他候选。本人核对原话是当前合同的确认前提，并不要求将原话一并公开。

R0.2 沿用动态议题成员范围。新增成员可能读取仍在该议题分享的观点，因此界面必须在分享和邀请参与者时清楚提示这一点，不能写成“仅限现在列出的这些人”。若需要固定名单、单人私信或有效期限，须完成相应授权对象与撤权测试后再提供该承诺。

### 4.3 听懂、同意与承担分开

听者只能针对自己当前有权看到的议题观点发出理解核对，不能读取私人原话再作判断，也不能给自己提交核对。请求只对听者和表达者可见；主持人和管理员不因角色而获得旁观权限。

表达者选择“需修正”时必须填写具体修正；该结果不能显示为“已准确理解”。当前合同采用一次请求、一次回应，听者需要继续核对时重新发起并依据修正填写复述，界面应给出清楚的返回路径。选择当面交流仅记录意愿，不表示系统已经安排会面或问题已经解决。

源观点撤回、改写或分享表示改变后，相关核对停止当前读取和回应。完全相同的当前版本重新分享后可恢复原记录的可见性，但不得自动新增准确回应。这个控制防止失效来源继续传播，不等于删除了历史；历史导出、保存期限和共同记录更正仍需后续规则。

### 4.4 模型建议始终可以不用

模型默认关闭。未启用、未安装指定模型、超时、繁忙、输出不合格或权限变化时，界面说明具体可继续的手工路径，不使用模板文本伪装成功推理。本地建议只使用当前原话及本人本次提供的语境；返回文本不自动保存、确认或分享。

生成前后检查会话、账号、作者与原话版本。原话改写或账号被冻结时，旧结果不能显示为有效建议。结构校验只能保证输出形状，不证明转述准确；明确拒绝、条件、责任和不确定性应保留，由本人核对并通过独立样本评价，不能为了语气温和而把拒绝改成配合。
